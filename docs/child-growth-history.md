# Children's height and weight history

Family → a child profile → Growth now records dated height and/or weight, with optional notes. The date defaults to the current Homebase day; no measurements are inferred, imported from chat memories or populated from estimates. Height can be entered as total inches (40 inches = 3 feet 4 inches) or centimeters; weight as pounds or kilograms. A unit selector switches presentation before editing. Storage uses centimeters/kilograms without rounding the entered conversion; correcting notes preserves unchanged stored measurement values.

Latest height and weight are shown independently with their measurement dates, so a weight-only entry does not erase the last height. Active history is newest-first. Correct edits an entry in place. Remove archives an entry; Show removed measurements exposes Restore. Archived entries are excluded from latest summaries but retained. This feature records measurements; it does not calculate BMI, percentiles, diagnoses or medical recommendations.

Measurements live in the existing family profile's validated `measurements` array. Old profiles default to an empty history without a database migration. Legacy profile saves that omit measurements preserve the existing history. Dedicated save/archive/restore actions use existing household API authentication, same-origin checks and optimistic profile versions. Both authorized household adults can read/edit the shared history. Stale corrections fail rather than overwrite another edit. No access policy, Vault capability, Walmart feature, birthday, important-date, wishlist or ordinary profile field is changed.

Validation rejects invalid calendar dates, future measurement dates (using the household timezone), nonpositive/out-of-range values, empty entries, duplicate entry IDs and unknown profile/measurement IDs. At least height or weight is required; either may be omitted. Measurement actions only target child profiles. Up to 1,000 entries per profile are supported.

Tests cover input conversions and unit display, separate latest-height/weight dates, archived filtering, invalid inputs, shared persistence, correction/archive/restore, stale writes, preservation through legacy saves and unchanged wishlist/profile fields. A React DOM interaction test exercises correction without rounding original values and verifies Remove sends an archive action. TypeScript, focused lint and production build are checked before publishing. Existing project-wide legacy lint issues are outside this feature. Browser/mobile visual verification remains outstanding because managed browser preview is unavailable in this environment.
